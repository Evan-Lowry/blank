# blank.

blank. (repo and hosting name: Clean Copy) turns a shareable Crowdmark results link into a blank assessment PDF. It also runs a searchable Waterloo Assessment Bank. Use this checkout as the project root and start by checking `git status --short --branch`.

## Current product behavior

- The home page (`#home`, the default) is a hero that says only "Search for a course" over a large search box, with "or paste a Crowdmark link" under it, browse-by-course chips, and recently added exams (`GET /api/bank/summary`). The same search form moves from the header into the hero on home. The converter lives at `#converter` and starts centered. Each assessment has its own input. A paste can fill several inputs, but only distinct, valid `https://app.crowdmark.com/score/<uuid>` links are accepted from the pasted text. An invalid paste leaves existing inputs intact.
- **Prepare PDF** generates the blank PDF, checks for a duplicate, and immediately publishes a new file in the public assessment bank. It opens the first successful preview in the split view. The converter stays on the left. Show **Download all** above the results once the batch has at least two successful PDFs. It downloads those PDFs in one ZIP with distinct filenames.
- The assessment bank is public without sign-in. `#exam-bank` is a plain list of courses (Course, Exams, Latest term) from `GET /api/bank/courses`, filtered by the search box. A course page (`#exam-bank/MATH137`, or `#exam-bank/unknown` for entries with no detected course) is a list of that course's exams (Term, Type, Pages), newest term first, with a Type filter and **Download all**. Each row has Preview and Download buttons and a three-dot menu (Copy link, Report a problem). Previews open in the same split view. Course list, exam list and the home page's recently added list share one `.list` style and narrow-width rules. The current release made the previous pending submissions public. Keep previously rejected entries excluded. The old editor route remains for compatibility. Ordinary submissions have no approval step or editor-only preview.
- The server detects course, term, assessment type, and optional number from the fetched booklet path. Contributors have no classification selector. **Only assessments whose course, term, and type are all recognised are added to the public bank.** Anything else is stored hidden (status `pending`) so the person who converted still gets a preview and download, and the row says it was not added to the bank. Every public list also hides entries with no course. To loosen the rule, change the `recognised` check in `saveExam` (`worker/exam-bank.js`).
- Use the browser’s built-in PDF viewer in an iframe for all previews. The same generated PDF displayed in desktop Safari when served from a direct same-site URL, while the embedded `blob:` URL left the pane blank. Keep the inline HTTP route, and keep the preview pane free of a second download button.

- Layout follows UW Flow and MathSoc (header search, hero landing page, flat lists with quiet row buttons; header and pages share one 68rem container) in a dark-only black/gray/white palette. There is no light theme. The accent is Electric blue (`#3d8bff`). The page background is a aurora glow (three colours) with faint contour lines faded in from the top, drawn by `body::before` and `body::after`; the colours are the `--aurora-1`, `--aurora-2` and `--contour` variables. The glow layers are absolutely positioned at the top of the page and drift at half speed as you scroll (`--scroll-y`, skipped under reduced motion). The list header row and list rows are transparent, so the background shows through; only the viewer, menus and dialogs are solid. Colors are variables at the top of `web/index.html`; `--accent` drives primary buttons, focus rings, and the selected-row bar. The brand is the lowercase wordmark "blank." with the period in the accent blue and a matching blue-dot favicon. The header has Convert and Assessments links, and the wordmark returns to the home page. Restrained copy.
- A small footer (Home, About, GitHub) sits at the bottom of every page, and `#about` is a short About page (what blank. does, what is and is not stored, public-bank notice, not affiliated with Waterloo or Crowdmark). There is no Email link yet because the owner has not chosen a public address; do not publish the owner's personal or university address without asking.
- **Paste anywhere:** pasting a shareable Crowdmark link into the search box or onto the page (outside any other input) opens `#converter` with the link filled in and focus on Prepare PDF. It never starts converting by itself, because converting publishes to the public bank. The same prefill is reachable at `#convert=<url-encoded link>` (the bookmark on the About page uses it). The link stays in the `#` part, so it is never sent to a server, and the page replaces it with `#converter` straight away. The bookmark only works from a `/score/<uuid>` shareable-results page.
- **Lists:** there is no star. Each row's three-dot menu has **Add to list…**, which shows your lists with ticks (tick as many as you like) and **+ New list**. A small blue dot beside a row's type means it is in at least one of your lists. The **Lists** nav link (`#lists`) shows your lists, `#lists/<id>` opens one (Copy share link, Download all, and a three-dot menu with Rename and Delete list), and **New list** creates one and drops you into naming it. Lists live in `localStorage` (`blank-lists`: up to 20 lists of 60 assessments) with no accounts. A share link is `#list=<ids>&name=<name>`, which anyone can open read-only and copy with **Add to my lists**. Starred items from the first version are migrated into a list called Saved. `GET /api/bank/exams?ids=...` returns up to 60 approved assessments.
- **Sync (no accounts):** the **Sync** button on the Lists page turns on sync, which creates a private 16-character code (`XXXX-XXXX-XXXX-XXXX`) and keeps one saved copy of the browser's lists in `sync_profiles` (D1, migration `0005`). Only a SHA-256 hash of the code is stored, and the code travels in the `X-Sync-Code` header of `/api/sync` (POST creates, GET reads, PUT saves with `baseVersion` and returns 409 plus the latest copy on a conflict, DELETE turns it off), so it never appears in a URL. Another device connects by entering the code. The client merges by list id and unions assessments, so syncing never loses anything. It syncs on page load, when the tab becomes visible, and about 1.5 seconds after any list change. Turning sync off on one device deletes the saved copy and the other devices turn themselves off on their next sync, keeping their lists. New codes are capped by `MAX_DAILY_SYNC_PROFILES` (default 500). Only list names and assessment ids are synced, nothing else.
- Naming: the public name is the **Assessment Bank** (nav link: **Assessments**) because it holds tests, quizzes, midterms, finals and assignments, not only exams. URLs, routes, table names and filenames keep the older `exam-bank` / `exam` names so shared links and the database keep working.

## Source map and data flow

| Path | Responsibility |
| --- | --- |
| `web/index.html` | HTML, CSS, converter form, batch processing, ZIP download, shared native preview |
| `web/exam-bank.js` | Exam bank navigation, search, filters, listing |
| `worker/index.js` | Worker entrypoint, origin checks, request routing, Crowdmark export |
| `worker/exam-bank.js` | Metadata detection, storage, deduplication, lists, PDF responses |
| `worker/pdf.js` | Generates a PDF using JPEG pages and records their byte offsets |
| `scripts/build.mjs` | Builds the Sites worker and the optional GitHub Pages frontend |
| `drizzle/` | D1 schema and migrations. Update `meta/_journal.json` when adding a migration. |

- `POST /api/export` retrieves Crowdmark's original exam-master booklet pages, then sanitizes and assembles the JPEGs. It cannot recover missing booklet pages. It publishes only the reconstructed blank copy and basic exam metadata. Keep original Crowdmark results links, grades, and student work out of stored or public records.
- The exporter returns the PDF for download and, when `nativePreview` is requested, `X-PDF-Preview` pointing to a two-hour inline PDF URL. The older `submitForReview` request field is a compatibility flag. Its name predates direct publishing. Published bank entries use `GET /api/bank/pdf/<id>?view=1` for previews. Omit `view=1` to download the file.
- The worker uses D1 (`DB`) and R2 (`BUCKET`). D1 stores metadata, deduplication hashes, and preview tokens. R2 holds the rebuilt PDF. SHA-256 checks identical PDF bytes, including compatible older entries without a hash. Preserve deduplication across simultaneous requests. Two visually similar PDFs may have different bytes.
- `GET /api/bank/exams` lists public entries (filters: `course`, `exact`, `year`, `season`, `assessment`; `term` is kept for the older Pages frontend). `POST /api/bank/report` stores a problem report in `exam_reports` (reasons: `student-work`, `wrong-details`, `other`). Reports never hide an entry by themselves. Editors read them at `GET /api/bank/reports`, and until there is a review UI the owner can also query D1 directly.
- **Copy link** (`#exam-bank/<COURSE>/<id>` opens that course and auto-previews the exam) and **Report** live in each row's three-dot menu. **Download all** (ZIP, up to 60 exams) is on the course page. The header search lists recent courses from `localStorage` when focused and empty, and `/` focuses it.
- The frontend uses plain browser JavaScript. The build inlines `web/exam-bank.js` into the HTML and bundles `fflate` as a same-origin asset. The assessment bank has no upload path; entries come only from Crowdmark conversion. `fflate` creates batch ZIP files in the browser. Edit the sources above and regenerate the output directories.

## Local development and checks

```sh
npm ci
npm run build
npm run dev
```

The local URL defaults to `http://127.0.0.1:4183/`. Set `CLEAN_COPY_PORT` to override it. `npm run dev` loads the built output with local stand-ins for D1 and R2 (`scripts/local-bindings.mjs`). Data persists in the git-ignored `.local/` folder; delete it to reset. Stub Crowdmark's response with synthetic JPEGs for write tests.

Useful checks are `node --check web/exam-bank.js`, `node --check dist/server/index.js`, and `git diff --check`. Smoke-test invalid and multi-link paste, immediate public listing for a fresh PDF, exact duplicates, native Safari preview, and ZIP download with two successful results. Use synthetic files for writes. The live exam list and existing public PDFs are safe read-only smoke checks.

## Hosting and publishing

- [Live Clean Copy on Sites](https://crowdmark-clean-copy.rbrlwy.chatgpt.site/) is the current development deployment and hosts the Worker, D1, and R2. The existing project ID and bindings are in `.openai/hosting.json`. Keep this project and its storage.
- Iterate locally or publish to the existing Sites project. Routine changes should stay off GitHub Pages. Sites deployment requires access to that project's source and publish tooling. Codex used the Sites connector to sync the source, push the exact commit, package the build and migrations, save a version, and deploy it. Claude Code may only have the local checkout. If it lacks Sites tooling, leave changes ready locally and say where deployment is blocked.
- [GitHub Pages](https://evan-lowry.github.io/clean-copy/) is an older static frontend from [Evan-Lowry/clean-copy](https://github.com/Evan-Lowry/clean-copy). It still calls the Sites backend. `npm run build:pages` creates the static `pages-dist/` output if the user explicitly requests a GitHub Pages release. Do not push this checkout to that repository. Use it for current source and preserve compatibility with the older frontend when changing public API contracts.
- **Cloudflare (free plan) is the production host.** `wrangler.jsonc` binds `DB` (D1, `drizzle/` as migrations) and `BUCKET` (R2 `blank-assessments`), and `DEPLOY.md` has the one-time setup. `npm run cf:dev` runs the built Worker under Cloudflare's local runtime (tested: migrations, list/report/ids endpoints, R2 PDF streaming), and `npm run deploy` builds and deploys. Live at https://blank.crowdmark-clean-copy.workers.dev (workers.dev subdomain `crowdmark-clean-copy`, D1 `blank`, R2 `blank-assessments`). `npm run cf:push-local` (dry run; add `-- --yes` to upload) copies local assessments to the live bank. A free-plan guard (`checkPublishLimits` in `worker/exam-bank.js`) pauses publishing at `MAX_STORED_PAGES` / `MAX_DAILY_PUBLISHES` from `wrangler.jsonc`; see `DEPLOY.md`. The Sites-only `oai-authenticated-user-*` editor headers do nothing on Cloudflare. Sites stays as the older development deployment.
- **Source remote:** `origin` is the private repository [Evan-Lowry/blank](https://github.com/Evan-Lowry/blank) (`main`). Push this checkout there only. [Evan-Lowry/clean-copy](https://github.com/Evan-Lowry/clean-copy) is the public GitHub Pages repository and must not receive this checkout. Local-only files stay untracked through `.gitignore` (`.local/`, `.wrangler/`, `.env*`, `.dev.vars*`, `dist/`, `pages-dist/`, `node_modules/`, `.claude/settings.local.json`).
- Keep access tokens and runtime secrets out of source and handoff files. Runtime settings belong in Cloudflare (`npx wrangler secret put NAME`) or Sites. Never use someone’s real Crowdmark results URL for a write test unless they explicitly want that assessment to be published.
